[size=5][b]Oblivion Frame Fixes[/b][/size]

Three small fixes that make Oblivion smoother, in one xOBSE plugin. Works flat and in VR.

[size=4][b]What it fixes[/b][/size]
[list=1]
[*][b]A precise frame clock.[/b] Oblivion measures how long a frame took with GetTickCount, in whole milliseconds. A 60 Hz frame of 16.67 ms reads as 16 or 17, a 144 Hz frame of 6.94 ms as 6 or 7 - so every animation and everything that moves speeds up and slows down by that much, frame by frame. On Windows the tick itself can jump in 16 ms steps when nothing has raised the timer resolution (the "64 Hz bug" that Stutter Remover and Display Tweaks fix in their way). This plugin gives the frame its real length from the high resolution counter, right inside the game's own clock code.
[*][b]A faster vertex copy.[/b] Every person in view is copied into the game's vertex buffers every frame, one memcpy call per vertex, 8 or 12 bytes each. With a few people around that was a fifth of the time a frame takes to draw. The plugin replaces that copy with one that does the same thing without the call per vertex. Same bytes, same places; only the clock can tell the difference.
[*][b]A faster script variable lookup.[/b] When an OBSE expression reads a variable of another script ("SomeQuest.someVariable"), xOBSE searches that script's variable list from the start, every single time. Mods with one big quest script pay for that: Maskar's Oblivion Overhaul's has 3532 variables, and when it builds its world events on leaving a house the game froze for 130 ms. The plugin remembers where each variable of a long list sits and answers by number. Same variables, found faster.
[/list]

[size=4][b]Requirements[/b][/size]
[list]
[*][url=https://github.com/llde/xOBSE]xOBSE[/url]
[*]Oblivion 1.2.0.416 (Steam, GOG, or retail patched to 1.2.0.416)
[*]For the variable lookup: xOBSE 22.13 (with another version that part simply stays off)
[/list]

[size=4][b]Install[/b][/size]
Install with your mod manager, or copy both files into [i]Data\OBSE\Plugins\[/i]:
[list]
[*]OblivionFrameFixes.dll
[*]OblivionFrameFixes.ini
[/list]
To remove it, just delete them.

If you use DXVK, add one line to your [i]dxvk.conf[/i] next to Oblivion.exe:
[code]d3d9.cachedWriteOnlyBuffers = True[/code]
The game writes its vertex buffers through a copy, and DXVK may put those buffers into video memory, where that copy runs at PCIe speed - up to a millisecond a frame with people in view on the test machine. The line keeps them in system memory.

[size=4][b]Settings[/b][/size]
In [i]OblivionFrameFixes.ini[/i]:
[code][Main]
PreciseFrameClock=1
FastStreamCopy=1
FastVariableLookup=1

[Diagnostics]
FrameClockTrace=0
StreamCopyCheck=0
VariableLookupCheck=0[/code]
[list]
[*][b]PreciseFrameClock[/b], [b]FastStreamCopy[/b] and [b]FastVariableLookup[/b]: 1 turns the fix on, 0 leaves that part of the game as it is.
[*][b]FrameClockTrace[/b]: 1 writes a line every ten seconds with the frame lengths the game's own clock produced and the lengths the frames were given. Good for seeing the problem on your machine; off for play.
[*][b]StreamCopyCheck[/b]: 1 does every vertex copy twice, the game's way and the fast way, and compares them byte for byte. Slow; only for checking.
[*][b]VariableLookupCheck[/b]: 1 looks up every variable both ways, uses xOBSE's answer and logs any difference. Slow; only for checking.
[/list]
[i]OblivionFrameFixes.log[/i] in the game folder says what the plugin did.

[size=4][b]Good to know[/b][/size]
[list]
[*][b]Oblivion 1.2.416 only.[/b] The fixes patch spots in the game's code; the plugin checks the bytes there first and does nothing if they are not the game's own. The log says which.
[*][b]The variable lookup patches one spot in xOBSE itself[/b] and works with xOBSE 22.13 only; with another version it finds other bytes there and leaves xOBSE's search alone. The real fix belongs into xOBSE; until a version has it, this is the stopgap.
[*][b]OBVR[/b], the VR mod, carries the first two fixes itself, not the third. With OBVR you only need this plugin for the variable lookup; for the other two, whichever comes second finds the spot patched and steps aside. Harmless.
[*][b]Display Tweaks and Stutter Remover[/b] replace GetTickCount for the whole game. This plugin changes only the frame's length, one level below that, so they can be used together: the plugin's precise length wins for the frame, theirs still serves the game's other timers.
[*][b]Measured so far[/b] in VR under Proton with DXVK, in the people-heavy opening scene: the scene render a fifth to a quarter faster with the fast copy (3.22 ms before, 2.37 to 2.57 ms with it and the dxvk.conf line); the game's clock reading 13 or 14 ms at 75 Hz before the fix and 13.33 after; and with StreamCopyCheck=1 522,000 vertex copies compared with the game's own, 0 differences. With one world render a frame, as on a monitor, and five people in view the frame's work fell from 5.43 to 5.06 ms, the copy itself from about 1.2 to 0.7 ms. The Windows tick is still to be measured; FrameClockTrace=1 shows it on your machine. Display Tweaks was loaded in the test game throughout, without a conflict.
[*][b]The variable lookup, measured[/b] under Proton with Maskar's Oblivion Overhaul, leaving a house and walking onto new ground, everything else the same: MOO's world event build on leaving the house 127.6 ms without the fix, 30.4 ms with it; the longest frame there 164 ms without, 76 ms with (those 76 ms are the first draw of the new view, not the scripts). A frame where MOO generated one of its dungeons: 117.6 ms of scripts without, 55.7 ms with (not the same dungeon - MOO places them at random - but about as many script runs, 3876 and 4037). With VariableLookupCheck=1 800,000 lookups compared with xOBSE's own, 0 differences. The rest of the time scripts cost about 0.1 ms a frame either way.
[/list]
